With [`@lit-labs/ssr`](https://lit.dev/docs/ssr/overview/), a Vite dev server
can render Lit components to HTML with declarative shadow roots, and the
browser hydrates them in place. The plugin runs on both halves: it hot-patches
the hydrated components, keeps the server's next render in step with your
edits, and lets sheet modules render on the server. The
[SSR example](https://github.com/oddcelot/vite-plugin-lit/tree/main/examples/ssr)
is a complete setup.

## What works

- **Hot patches on hydrated components.** An edit patches a hydrated component
  in place, keeping its state and its element, as on a page the browser
  rendered.
- **The next server render.** Vite re-runs the edited module for the next
  render, which defines the element again. The plugin lets the server's
  registry take the new class, so a reload shows the edit instead of failing
  because the tag is already defined.
- **`defer-hydration`.** An element held back by `defer-hydration` that you
  edit before it wakes keeps the server's HTML on screen, then renders the
  edited template when the attribute goes.
- **Sheet modules.** A `?css-sheet` import no longer throws in Node. Its css is
  written into the component's declarative shadow root, so the page arrives
  styled, and once the component hydrates it adopts the real sheet, so css
  edits hot-swap it. See
  [Share one stylesheet with ?css-sheet](/vite-plugin-lit/guides/stylesheets/css-sheet/#choose-the-build-output).
- **A page older than your edit.** If the HTML predates an edit, the
  component renders in the browser once instead of failing to hydrate and
  later showing twice.
- **Hydration state in the DevTools.** The Components tab marks a
  server-rendered component _deferred_, _not hydrated_ or _SSR_ (hydrated).

## Limits

The plugin leaves the server's own modules untransformed: no HMR wrappers, no
source stamps and no timeline events on the server.

Lit's hydration expects the client's template to match the server's HTML. A
page loaded in the instant between an edit reaching the server and reaching
the browser carries HTML from the old template. The plugin catches the
mismatch and renders that component in the browser instead, with a console
warning that names it. Nothing is lost, since a component has no state before
it hydrates, but it is a client render, not a hydration.
