One integration renders your Lit components in Astro and hydrates them, hot
patches them while you edit, and puts the Lit panel in the dev toolbar. Read
[Server-side rendering](/vite-plugin-lit/guides/ssr/) first if hydration is
new to you.

## Set it up

Install the plugin with Lit's server renderer and its hydrate support.

```sh frame="terminal"
npm install lit @lit-labs/ssr @lit-labs/ssr-client
npm install -D @oddsquad/vite-plugin-lit
```

Add `lit()` from `@oddsquad/vite-plugin-lit/astro`. It takes the plugin's
[options](/vite-plugin-lit/reference/options/) and turns the timeline on,
since the panel needs it.

<Code code={config} lang="js" title="astro.config.mjs" mark={[5]} />

Import each component in the page's frontmatter, so Astro renders it, and in
a page script, so the browser defines it. The integration loads Lit's hydrate
support ahead of your scripts, so the server's HTML hydrates instead of
rendering again.

## Pass props

Strings, numbers and booleans become attributes, under the attribute of the
reactive property they name. Arrays, objects and properties declared with
`attribute: false` can't ride in an attribute, so the renderer sets them as
properties and holds the element back until the browser has them too.

<Code
  code={stripHeader(tagList)}
  lang="ts"
  title="src/components/tag-list.ts"
  mark={[31]}
/>

On a plain tag, the values travel as JSON in a `data-lit-props` attribute. In
an island, Astro hands them over itself, with its own serialization.

<Aside type="note" title="Functions need an island">
  JSON can't carry a function or a class instance. On a plain tag the renderer
  leaves such a prop out and warns in the terminal. Make the element an island
  to pass it.
</Aside>

## Choose when it hydrates

A plain tag hydrates as soon as its class loads. Write `defer-hydration` on
it to hold it back, and remove the attribute when it should wake: the
renderer leaves your `defer-hydration` alone.

An imported class used as a component is an island, so Astro's directives
apply: `client:load`, `client:idle`, `client:visible` and `client:media`
hydrate the server's HTML, and `client:only` renders in the browser only.
With more than one renderer in the project, name this one for `client:only`:
`client:only="@oddsquad/vite-plugin-lit"`.

## Open the panel

Run `astro dev` and click the Lit logo in the dev toolbar. The panel opens in
a toolbar window, following the page you are on, with each element's
hydration state in the Components tab.

The first time, the window asks for a code. The terminal prints it in a
`Devframe` box when the panel connects. Type it in, or open the link in that
box: it loads the page with the panel open and approved.

<Aside type="caution" title="Client auth guards the panel">
  The code stops other pages and devices that reach the dev server from driving
  the panel, which can write files and open your editor. Turn it off only on a
  machine you trust, with `VITE_DEVTOOLS_DISABLE_CLIENT_AUTH=true`.
</Aside>

## Keep another renderer

To keep a different Lit renderer, such as `@awesome.me/astro-lit`, use
`litDevtools()` instead of `lit()`. It brings the plugin's HMR and the panel,
and leaves rendering to the other integration.

## Limits

Astro renders pages without Vite's `transformIndexHtml`, which is how the
plugin adds its page runtime. In dev the integration adds it to each HTML
page itself, so Astro sends a page once it is complete, not as a stream.

Every current browser parses declarative shadow roots. For an older one,
install `@webcomponents/template-shadowroot` and pass
`shadowRootPolyfill: true`.
