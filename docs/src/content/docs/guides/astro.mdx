One integration gives an Astro site hot patches on its Lit components and the
Lit panel in Astro's dev toolbar. Astro renders Lit on the server through
[`@awesome.me/astro-lit`](https://github.com/shoelace-style/astro-lit), so
read [Server-side rendering](/vite-plugin-lit/guides/ssr/) first if hydration
is new to you.

## Set it up

Install the plugin next to the Lit renderer and its polyfill.

```sh frame="terminal"
npm install lit @awesome.me/astro-lit @webcomponents/template-shadowroot
npm install -D @oddsquad/vite-plugin-lit
```

Add both integrations. `litDevtools()` takes the plugin's
[options](/vite-plugin-lit/reference/options/) and turns the timeline on, since
the panel needs it.

<Code code={config} lang="js" title="astro.config.mjs" mark={[4, 22]} />

Import the components in the page's frontmatter, so Astro renders them. Load
`astro-lit`'s hydration support in a page script before any component, so the
server's HTML hydrates instead of rendering again.

## Open the panel

Run `astro dev` and click the Lit logo in the dev toolbar. The panel opens in
a toolbar window, following the page you are on. The terminal prints its
address too, under `Lit DevTools`, for a tab of its own.

The first time, the window asks for a code. The terminal prints it in a
`Devframe` box when the panel connects. Type it in, or open the link in that
box: it loads the page with the panel open and approved. The browser keeps
the approval until the dev server forgets it.

<Aside type="caution" title="Client auth guards the panel">
  The code stops other pages and devices that reach the dev server from driving
  the panel, which can write files and open your editor. Turn it off only on a
  machine you trust, with `VITE_DEVTOOLS_DISABLE_CLIENT_AUTH=true`.
</Aside>

## Hold back hydration

`astro-lit` removes `defer-hydration` from every element outside an island
once its class loads. A plain element held back that way hydrates at once.
Make it an island instead, and let a client directive pick the moment. The
example adds `client:on`, which hydrates on a click elsewhere in the page:

<Code code={directive} lang="js" title="directives/on.js" />

Astro's own `client:visible` and `client:idle` work the same way.

## What works

- **Hot patches on hydrated components.** An edit patches a component in
  place, keeping its state and its element, in islands and outside them.
- **The Lit panel.** The Components tab lists the page's components with
  their hydration state, as in a Vite app.
- **The HMR indicator and the source overlay.** Both run in the page as they
  do with Vite.
- **Production builds.** `astro build` applies the plugin's build-time CSS
  handling and adds no devtools code.

## Limits

Astro renders pages without Vite's `transformIndexHtml`, which is how the
plugin adds its page runtime. In dev the integration adds it to each HTML
page itself, so Astro sends a page once it is complete, not as a stream.

The panel lives in the toolbar here, not in the Vite DevTools dock. Leave
Vite's `devtools` option off: with the dock on, the plugin serves the panel
there instead, and the toolbar window has nothing to load.
