See what a save costs you in a Lit project today, and what changes with the
plugin. Already convinced? Go straight to [Installation](/start/installation/).

## A save costs you your place

Vite's hot module replacement works for frameworks that bring a runtime to
swap components. Lit has none, and the browser refuses to define a custom
element tag twice. So when you save a Lit component, Vite reloads the page.

The reload takes everything you had built up: the count you clicked to, the
text half-typed into a field, the open menu, the scroll position, the step
of the form you were testing. You click your way back, check the change, and
save again.

## The plugin patches the class in place

The plugin catches the second `customElements.define()` and updates the class
the browser already registered. The elements on the page are the same
elements, so their state stays where it was. Only the markup you edited
changes.

## Three more things you get

**CSS edits that keep the page.** A component that takes its CSS from a
file, imported with `?inline` and handed to `unsafeCSS()`, reloads the page
on every save of that file too. Import it with `?css-sheet` instead and every component
that imports it, of any class, adopts one shared `CSSStyleSheet`. A save
swaps that sheet's text: every shadow root restyles in place, no component
re-renders, and the page keeps its state.

**A panel that explains re-renders.** The DevTools panel shows the live
component tree, each update with what triggered it and how long it took, and
a timeline of the whole session. Your coding agent can read the same data
over MCP.

**Every component's docs where you debug.** Select an element and the panel
shows its summary, what each property is for and the events it fires. Your
own components are read from their JSDoc; a library's come from the Custom
Elements Manifest it ships, so Web Awesome is documented with no setup.

The [feature tour](/overview/tour/) shows each of these running.

## What it asks of you

- **One line of config.** `litPlugin()` in your Vite config turns on hot
  patching and the CSS import queries. The panel and the source overlay are
  opt-in.
- **Vite 7 or 8, and Lit 3.** The [compatibility page](/reference/compatibility/)
  has the full matrix.
- **Nothing in production.** Patching, the indicator and the panel run on the
  dev server only. A production build ships your components and nothing else.
- **A few shapes still reload.** Standard `accessor` decorators, a changed
  `observedAttributes` list and module-level state are the main ones. The
  [limitations page](/reference/limitations/) lists each with its workaround.
